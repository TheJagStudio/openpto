# OpenPTO web

Angular front end for OpenPTO: patent and trademark search, a fee calculator, the XML → JSON data pipeline, a developer portal, system status and an admin console. The browser only ever talks to the **gateway** (`:8080`), using relative URLs.

| | |
|---|---|
| Framework | Angular **22.2** (standalone, zoneless, signals, `rxResource`, OnPush everywhere) |
| UI kit | **ZardUI** (shadcn-style, copied into `src/app/shared/`) via `zard-cli` 1.0.0-beta.117. `@ngzard/ui` is deprecated and renamed to `zard-cli`. |
| Styling | **Tailwind CSS 4.3** via `@tailwindcss/postcss` (`.postcssrc.json`), design tokens in `src/styles.css` |
| Icons | `@ng-icons/lucide` |
| Tests | Vitest 5 + jsdom through `@angular/build:unit-test` (Jasmine-style `describe/it/expect`, `vi.fn()` for spies) |

## Run

```powershell
. D:\JavaSpring\tools\env.ps1        # local Node 24 + npm prefix/cache
cd D:\JavaSpring\projects\openpto\web
npm install
npm start                            # ng serve on http://localhost:4200; proxy.conf.json → gateway :8080
npm run build                        # production build → dist/web/browser
npm test -- --watch=false            # headless unit tests (jsdom, no browser needed)
```

`proxy.conf.json` forwards `/api`, `/v3`, `/.well-known`, `/gateway` and `/swagger-ui*` to `http://localhost:8080`. In production the SPA is served from S3 + CloudFront, and CloudFront sends `/api/*` to API Gateway, so the relative URLs don't change (`src/environments/`).

## Structure

```
src/app/
  core/
    models/        typed DTOs that mirror docs/CONTRACTS.md (Page<T>, ProblemDetail, PatentDetail, FeeQuote, IngestJobResponse…)
    api/           one service per resource: PatentsApi, TrademarksApi, FeesApi, IngestApi, AuthApi, AccountApi, StatusApi
    http/          functional interceptors (X-Request-Id, Bearer JWT, errors), toHttpParams/toPage, ProblemDetail helpers
    auth/          AuthStore (signal store in localStorage, expiry-aware) + authGuard / adminGuard / guestGuard
    notify/        Notifier: toast facade over ZardUI sonner
    title.strategy.ts, format.ts, status-tone.ts
  layout/          shell (sticky top nav, mobile sheet nav, user menu, theme toggle, footer, toaster)
  ui/              app-level building blocks: status badge, pager, SVG bar chart, JSON viewer, code tabs, copy button, error state…
  features/        lazy-loaded pages
    landing/  patents/  trademarks/  fees/  pipeline/  developers/  status/  admin/  auth/  not-found/
  shared/          ZardUI components, core and utils (generated by zard-cli, lightly patched, see below)
```

## Design decisions

- **The URL is the state for search.** `/patents?q=…&type=…&page=…` is parsed by a pure function (`parsePatentQuery`) into typed criteria. Results and facets are `rxResource`s keyed on the criteria, so back/forward and shared links just work. Typing is debounced (350 ms) and uses `replaceUrl`. Facets reload only when a filter changes, not on paging.
- **Errors are ProblemDetail everywhere.** `errorInterceptor` shows a toast with title, detail and `requestId`. On 401 it drops the session and redirects to `/login?returnUrl=…`. On 429 it reads `Retry-After`. Calls that render errors inline (forms, 404 pages, live calculators, status polling) opt out with the `SKIP_ERROR_TOAST` HttpContext token. `SKIP_AUTH_REDIRECT` stops the login call itself from redirecting.
- **Tokens never leave the origin.** The auth and request-id interceptors only apply to same-origin URLs. `returnUrl` is sanitized, so it can't be used as an open redirect.
- **Fee calculator.** Reactive forms mirror the backend rules (claim ranges, independent ≤ total, Track One limits). Each change is debounced and fires three requests in parallel (one per entity size), which gives the comparison for free. Switching entity size doesn't refetch. The server stays the source of truth for amounts, and saved quotes are recomputed server-side.
- **Polling uses signals.** An `effect` schedules `reload()` while any visible job isn't terminal, and cleans up on change or destroy.
- **No heavy libraries.** The bar chart is hand-rolled SVG with an sr-only data table. The JSON viewer tokenizes and renders text nodes (no `innerHTML`, so payloads can't inject markup). `ngx-sonner` is the only extra runtime dependency, and it comes with ZardUI.
- **Accessibility.** Skip link, landmarks, labelled controls, visible focus rings, `aria-live` results counts and toasts, `aria-current` in nav and pager, keyboard-operable tabs, dialogs and menus, reduced-motion support, and AA-contrast status colours in both themes.
- **Theming.** Light, dark and system via ZardUI's `ZardDarkMode` (persisted under `theme`), plus an inline pre-paint script in `index.html` so there's no flash.

### Local patches to generated ZardUI code

- `card`: `z-card-title` and `z-card-description` now project content when no `zTitle`/`zDescription` input is given.
- `select`: new `zAriaLabel` input, so the trigger announces "Field: value". Upstream `zLabel` is a display override, not a label.
- `card` and `breadcrumb` `index.ts` files also re-export their `*.imports.ts`.
- `z-pagination` renders every page, so `ui/pager.component.ts` builds a windowed pager from its primitives.
- `z-breadcrumb-item[routerLink]` conflicts with `RouterLink` when both are in scope, so it's wrapped in `ui/breadcrumbs.component.ts`.

## Contract notes

- `GET /api/v1/admin/users`: the contract says "page of users with key counts" but doesn't name the field. The UI reads `apiKeyCount` and shows "—" if it's missing.
- `IngestJobResponse.stages[].status` values aren't enumerated. The stepper treats `DONE/SUCCEEDED/COMPLETED/OK` as done, `RUNNING/IN_PROGRESS` as active and `FAILED/ERROR` as failed.
- `GET /api/v1/ingest/jobs/{id}/json` needs a JWT, so the download goes through `HttpClient` as a Blob rather than a plain link.
- The job lists request `sort=createdAt,desc`.
